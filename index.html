      API v1.0

      Read-only · static JSON · no authentication

      The same published dataset as the map and the price table, served as ordinary JSON files — one envelope, full provenance, no keys and no build step on your side. The static files are generated from the snapshotted DOE workbook by the same pipeline, so the page, the CSV downloads and the API cannot disagree.

      Static JSON snapshots No auth, no cookies, no tracking Dataset version 2026-11-10 OpenAPI 3.1 contract

      Getting started

      Files live under api/v1/ relative to this page. Fetch them like any static file — there is no account, key, token or rate limit. The only requirement is a plain HTTP client:

      curl -s api/v1/health.json
curl -s api/v1/rates/latest/residential.json

      Every response uses the same envelope: meta (dataset version, source, attribution, licence and disclaimers, row count), data (the payload) and next_cursor (null — these are complete snapshots, not pages of a cursor stream).

      {
  "meta": {
    "api_version": "1.0",

    "attribution": "Department of Energy (DOE) — Electricity Rates & Power Market Monitor",

      Datasets & units

      All rates are in Philippine pesos per kilowatt-hour (₱/kWh), exactly as published by the DOE; no unit conversion, rounding or re-estimation is applied. Periods are ISO year-months (2026-10); timestamps are ISO 8601 with the source’s +08:00 offset.

      Conventions

      Envelope & metadata

      Clients can rely on the same three top-level keys in every file. meta.count is the number of rows in that response; meta.source identifies the publisher and canonical URL for the underlying data.

      Data states

      A rate cell is one of published, nda (the workbook says “No Data Available”), missing or invalid (the cell is not a number). Only published values ever appear in rate_php_per_kwh; nulls and their state are kept explicit. Aggregates always carry their reporting count.

      Static snapshots

      This is a snapshot API, not a query endpoint: files are not paginated and there are no ?limit or ?filter parameters. Filter and aggregate client-side, or download the CSV files for larger work. A new workbook retrieval produces a new dataset_version; fields never change meaning inside a version.

      Errors

      Unknown paths return the host’s normal HTTP 404; there is no JSON error envelope. A file that exists is always valid JSON. Treat non-200 responses or parse failures as “dataset unavailable” and retry later.

      Caching & fair use

      Files are safe to cache; use conditional requests (ETag / If-None-Match) where the host supports them. Usage is free; identify heavy automated clients with a descriptive User-Agent and prefer the bulk CSV files for full-dataset work.

      Versioning

      The API version is v1 in the path; the dataset version is the retrieval date in meta.dataset_version. Additive fields may appear in a minor release; breaking changes move to /v2. The contract is versioned in openapi.yaml.

      Source conflicts & limits
      
      
      The four tabs disagree in 5 places. The pipeline keeps the losing
      claims and resolves by majority — it does not silently pick a value.
      
      
      region conflict · source row 33canonical: BARMM. BARMM in residential, commercial, generation · Region 12 in industrial — resolved by majority
      island conflict · source row 33canonical: Mindanao. residential tab: Mindanao · commercial tab: Mindanao · industrial tab: BARMM · generation tab: Mindanao — island label contradicts the region's island group; region mapping used
      grid conflict · source row 122canonical: CONFLICT. ONGRID in residential, generation · OFFGRID in commercial, industrial — 2–2 split between ONGRID and OFFGRID — published as CONFLICT, not guessed
      grid conflict · source row 123canonical: CONFLICT. ONGRID in residential, generation · OFFGRID in commercial, industrial — 2–2 split between ONGRID and OFFGRID — published as CONFLICT, not guessed
      name variant · source row 166canonical: DANECO/NORDECO. generation tab: DANECO — same workbook row is labelled differently in another tab

      Service areas behind the provider filter
      
      
      The DOE workbook publishes each distribution utility once, under a single region. That is
      enough for a regional median, but it is not the utility’s service area. The provider lens
      maps every utility onto the cities and municipalities it is franchised to serve, using three
      sources in descending order of authority:
      
      
        
        
      • Meralco — the current franchise law (RA 12146, 11 April 2025,
        Section 1) enumerates the territory: all of Metro Manila, Bulacan and Rizal; parts of
        Cavite, Laguna, Quezon and Batangas; and 17 barangays in Pampanga. That list is mapped
        LGU-by-LGU to PSGC 3Q 2026, and the law wins over any secondary source.
        • 
        
      • Other distribution utilities — LGU-level franchise areas compiled
        from DOE franchise records in the OpenStreetMap Wiki operator table (CC BY-SA 2.0),
        cross-checked against each utility’s DOE region.
        • 
        
      • Fallback — where no LGU-level service area is sourced yet, the
        DOE workbook region is published as a single region-level coverage area and labelled as
        such, never guessed.
