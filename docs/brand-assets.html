Brand usage. The BetterGov emblem and wordmark are BetterGov.ph brand assets, not open-source artwork. This page uses them unmodified, for this BetterGovPH open-data project — the same brand-usage position already recorded in draft/assets/README.md. Before public deployment, confirm logo/brand usage with the brand owner. Rules followed here:

  • path data and proportions are never redrawn — the files are the official drawings with editor cruft (<defs><style>, classes, ids) stripped;
  • no recolouring: the emblem uses only official navy #0032a0 and white;
  • the emblem is never stretched (always square), never outlined, never given a drop shadow; keep clear space around it (≥ ¼ of the disc diameter) and do not place it on busy imagery;
  • the page presents itself as an open-data product, not as an official DOE or BetterGov publication (see the page footer/source notes).

The single derived use is the favicon mark: ../favicon.svg scales the emblem's own inner sun/Sarimanok mark from the official path data onto the official navy field. The emblem's circular "BETTER GOV PILIPINAS" ring text is unreadable below ~40 px, so the derived mark keeps the brand recognisable at 16–32 px. Nothing is redrawn; the mark is only translated/scaled. If the brand owner prefers the strict official favicon, substitute https://data.bettergov.ph/BetterGov_Emblem-Outline-Inversed.svg (our emblem-outline.svg is that same file, optimised) — the full badge is legible from ~40 px up (see proof sheet favicon-before-after.png).

Fonts (OG card only)#

draft/assets/fonts/*.woff2 — Figtree, Inter, JetBrains Mono (latin variable subsets via Google Fonts), SIL Open Font License 1.1. They are embedded as data URIs in the OG card at render time; the final og.png contains no font files or network references.

Regeneration#

The SVGs (emblem.svg, emblem-outline.svg, favicon.svg, icons.svg, icons.json) are the sources. The rasters are generated from them:

bash
# from the repo root
node draft/assets/brand/render-assets.mjs

Overrides if playwright-core / Chromium live elsewhere:

bash
PLAYWRIGHT_CORE=/path/to/node_modules/playwright-core \
CHROME_PATH=/path/to/chrome \
node draft/assets/brand/render-assets.mjs

The script (headless Chromium via playwright-core, no downloads, no network):

  1. builds the OG HTML from og-card.template.html by inlining draft/assets/fonts/*.woff2 (data URIs), draft/assets/bettergov-logo.png and emblem.svg; asserts the page makes zero non-data:/file: requests; screenshots exactly 1200×630 → draft/assets/og.png;
  2. rasterises draft/assets/favicon.svg at 32/192/512 → favicon-*.png (opaque, white-matted, RGB);
  3. rasterises the official emblem on white at the official 91.7 % scale → apple-touch-icon.png (180×180, opaque).

It prints bytes + sha256 for every output and fails if a PNG is not the expected size or not opaque RGB. Rendered bytes depend on the Chromium build (a different Chromium/font build may produce different PNG bytes/checksums); the SVG and JSON markup is deterministic in any environment.

How the page builder consumes these#

tools/build-map-page.py reads them at build time and inlines them:

  • Emblem — load_emblem() reads emblem.svg verbatim and prepends class="emblem"; emblem() emits it at the masthead and footer. The file has no <style>/<defs>/classes, only plain fill attributes, so no CSS collision can repaint it. It has no width/height: size it in CSS (.emblem), keep it square. Sizing advice: masthead 40–46 px, footer 32–36 px; drop the old .masthead-mark blue tile behind it (the emblem is already a navy disc) — the decision sheet is /tmp/brand-proof/masthead-options.png; use emblem-outline.svg on navy/dark backgrounds.
  • Icons — load_icons() merges icons.json.icons into the builder's ICONS; icon(name) emits <svg class="i" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="1.75" stroke-linecap="round" stroke-linejoin="round">{body}</svg>. Values are objects with viewBox and body, which the builder already unwraps. Alternatively inline icons.svg and reference <svg class="i"><use href="#i-<name>"></use></svg>. Pick an icon by name only — never paste path data into templates.
  • Favicon — draft/assets/favicon.svg is base64-inlined as <link rel="icon" type="image/svg+xml">; apple-touch-icon.png is inlined as <link rel="apple-touch-icon" sizes="180x180">. The PNG ladder (32/192/512) is available for deployments that prefer bitmaps or for a web app manifest.
  • OG card — draft/assets/og.png sits beside the built page as assets/og.png; the builder points og:image at it when OPEN_ENERGY_SITE_URL is set (1200×630, so it also declares og:image:width/height).

Verification performed (10 Nov 2026)#

  • emblem.svg is pixel-identical to a render of the official source: 0 of 1,166,400 pixels differ at 1080×1080, and it round-trips through an XML parser (emblem-outline.svg, icons.svg, favicon.svg likewise XML-valid).
  • All four SVGs contain no <script>, <style>, <defs>, <image>, classes or external URLs (only the xmlns namespace).
  • The builder's own load_emblem() / load_icons() / icon() / emblem() were exercised against these files: 22 icons load and render, the emblem inlines and renders.
  • icons.json bodies are well-formed, contain no fill/stroke/class/style overrides, and every viewBox is 0 0 24 24.
  • All PNGs are opaque RGB at the exact expected dimensions; og.png is exactly 1200×630 and its render made zero external requests.
  • Proof sheets (generated during this task, not committed): /tmp/brand-proof/ — favicon-tab-proof.png (16 px tab icon, light+dark, 2× density), favicon-legibility-16-32-48.png, favicon-before-after.png, icons-legibility-16-20-24.png, icons-on-dark-24.png, icons-sprite-use-proof.png (sprite <use> integration), emblem-official-vs-optimized.png, masthead-options.png, brand-assets-overview.png, og-card-1200x630.png.

Caveats#

  • Brand permission for the emblem/wordmark is the one non-code dependency: this is a pre-release draft; clear public use with the brand owner before launch. Fonts and Lucide icons are properly licensed (OFL 1.1; ISC + MIT for Feather-derived icons) — keep the notices; repo-docs writes the consolidated NOTICE.
  • The favicon mark is derived (scaled official inner mark, explained above). If strict brand governance is required, swap ../favicon.svg for the official inversed outline file (emblem-outline.svg) and re-run the regeneration script — the tab icon gets softer at 16 px, but it is the exact official mark.
  • OG card text is data-dependent. “141 distribution utilities … 2018–2026” is the current dataset headline; if the ingested data changes, update og-card.template.html and re-run render-assets.mjs, otherwise the card and the page will disagree. The card is a static render — it is not regenerated by tools/build-map-page.py.
  • No font is shipped for the page’s own runtime by this directory; the OG card embeds the existing latin subsets only, so non-latin text would fall back if someone edits the card with non-latin glyphs.
