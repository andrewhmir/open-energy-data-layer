Architecture · documentation

Frontend architecture

draft/frontend.md · 331 lines · 37 KB · 4,979 words

Download raw All docs

The Open Energy Data Layer has three browser-facing surfaces, all generated by Python builders in tools/: the single-file product page, the generated documentation site, and the local review pack that serves both in a separate review context. There is no application server and no client-side framework — every page is static HTML, CSS and vanilla JavaScript rendered from data, markdown and design assets at build time.

This page is the map for changing that layer safely: where each piece is built, how data and assets are injected, how the product page's runtime state works, which ids and behaviours the QA suites pin, and which rules are non-negotiable. Read it with the repository's agent entry points — AGENTS.md at the repo root and draft/component-map.md — and the builder-by-builder map in tools/AGENTS.md.

1. Frontend surfaces and where they are built#

Surface Source of truth (edit here) Generated output Served at Committed?
Product page tools/build-map-page.py, data/seed/page-data.json, draft/assets/** draft/map-table-prototype.html — one self-contained file, roughly 1 MB review pack /prototype.html (a clean, chrome-free copy); also openable locally over file:// tracked; generated — never edit
Docs site tools/build-docs.py plus the registered markdown sources draft/docs/ (one HTML page per registered document + landing page) and docs-manifest.json review pack /docs/; also works from file:// tracked; CI fails on any diff
Review pack tools/build-preview.py plus the two surfaces above and the data/contract files preview/ — submission hub, submission pages, neutral platform review copies, files/ tree and zip https://devvm1.tailf19a1a.ts.net/ on the tailnet (HTTPS; also port 8099), not the public internet gitignored — never commit
Static JSON API (supporting data, not a UI) tools/build-api.py + draft/openapi.yaml draft/api/v1/** linked from the page and the docs; served under pack /files/draft/api/v1/ tracked

Three consequences shape every frontend change:

  • Tracked output means reproducibility is a contract. CI rebuilds draft/api/ and draft/docs/ and fails on any diff; python3 tools/validate.py --check-page copies the tree without .git, node_modules and preview/, rebuilds the page twice and compares it byte-for-byte with the committed file.
  • preview/ is disposable. It is rebuilt from tracked artefacts and is rebuilt last in the chain. Never treat a page under preview/ as source.
  • Other workspace files are not part of the product. The repository-root index.html and screenshots/ are unrelated files in this workspace; do not link them into a surface (see the "unrelated files" note in CONTRIBUTING.md).

2. Product-page anatomy#

2.1 Build-time data injection#

The page has no runtime data fetches: tools/build-map-page.py reads the seed payload, the geometry, the design assets and (optionally) the generated static API, then writes one HTML file with <style> and <script> inlined.

text
data/seed/page-data.json ──────────────┐
draft/assets/geo.json ─────────────────┤
draft/assets/coverage-geo.json ────────┤   tools/build-map-page.py            draft/map-table-prototype.html
draft/assets/fonts/manifest.json ──────┼─► TOKENS + shell + JS ─────────────►   (~1 MB: fonts, emblem, favicon,
draft/assets/brand/ (emblem, icons) ────┤   (one deterministic pass)              icons, map + LGU geometry,
draft/api/v1/*.json (optional) ────────┘                                         data all inlined)

The JS template is a plain string with five placeholders; main() replaces each with compact JSON (json.dumps(..., separators=(",", ":"))), escaping </ so no payload can close the <script> element.

Placeholder Source Injection Consumed as
__PAYLOAD__ data/seed/page-data.json main() var DATA — utilities with monthly series, regions, stats, source tabs, validation and conflicts
__API_TABS__ draft/api/v1/*.json via load_api_explorer() main() var API_TABS — six real response files (health, latest residential rates, utilities, one region, changes, one source), each trimmed to five rows by trim_example() with a "showing N of M" note
__LGU_GEO__ draft/assets/coverage-geo.json via coverage_blocks() main() var LGU — compacted LGU geometry: paths, names, province index, region labels, bounds
__COVERAGE__ page-data.json coverage records via coverage_blocks() main() var COV — per utility: detail level (region / lgu / barangay), regions, LGU indexes, barangay counts, source ids, notes
__COVERAGE_SOURCES__ page-data.json coverage sources via coverage_blocks() main() var COV_SRC — the coverage-source registry (publisher, title, URL, licence, attribution) behind the credit lines

Assets are inlined rather than injected as placeholders: font_faces() base64-embeds the three font subsets, load_emblem()/emblem() inline (or fall back to) the BetterGov mark, icon() inlines SVG from draft/assets/brand/icons.json (with an ICON_FALLBACK set), main() data-URI-encodes the favicon and optional apple-touch icon, and map_svg() inlines the region choropleth. The head also carries a <meta http-equiv="Content-Security-Policy"> that blocks every external load:

text
default-src 'none'; style-src 'unsafe-inline'; font-src data:; img-src data:;
script-src 'unsafe-inline'; base-uri 'none'; form-action 'none'; object-src 'none'

A schema.org Dataset JSON-LD block is always emitted; canonical and Open Graph URLs are added only when the optional OPEN_ENERGY_SITE_URL environment variable is set at build time, so leave it unset for an offline/deterministic build.

The static API tree is genuinely optional: load_api_explorer() skips missing files, so an empty __API_TABS__ renders an empty explorer rather than failing the build. Everything else in load() (page payload, region geometry, coverage geometry, fonts manifest) is required.

The CSS starts at the TOKENS constant (search for Design tokens: budget.bettergov.ph). It implements the BetterGovPH open-data design language shared with the docs site: white paper, ink and rule neutrals, BetterGov blue, Figtree / Inter / JetBrains Mono, tabular numbers.

3. Interaction and state model#

3.1 The single state object#

All interactive state lives in one plain object; render functions read it and mutations go through helpers that re-render and call syncUrl().

javascript
var state = {
  colorBy: 'residential',   // 'residential' | 'commercial' | 'industrial' | 'generation'
  region: 'all',            // PSGC region code, or 'all'
  utility: null,            // utility code whose table row is expanded
  provider: null,           // utility code for the map's service-area lens
  q: '',                    // free-text search
  type: 'all',              // 'PIOU' | 'EC'
  grid: 'all',              // 'ONGRID' | 'OFFGRID' | 'CONFLICT'
  includeNda: true,         // show utilities whose latest residential rate is NDA
  sortKey: 'residential',
  sortDir: 'desc',
  compare: []               // up to COMPARE_MAX (3) utility codes
};

Other module-level constants worth knowing: COMPARE_MAX = 3, COMPARE_COLORS (three fixed series colours), SORT_KEYS (name, region, type, residential, res_delta_pct, commercial, industrial, generation, status), CLASSES (the four customer classes) and the lookup maps UTIL, REGION, DDS.

3.2 URL and deep-link sync#

syncUrl() writes the current view into location.search with history.replaceState() — no history entries are created, and default values are omitted so a plain page URL stays clean. applyUrlState() runs near the end of init(), validates every parameter, and renders the matching view; unknown or malformed values are ignored.

Parameter Written when Read as
provider a map provider lens is active utility code; selects the provider and filters the table, if the code exists in both utilities and coverage
region a region filter is active PSGC code; selects the region and syncs both region dropdowns
compare two or more providers are selected comma-separated utility codes, capped at 3; opens the comparison dialog on load
q the search box is non-empty free-text query, restored into #q
type not all PIOU or EC
grid not all ONGRID, OFFGRID or CONFLICT
nda NDA rows are hidden 0 (the switch is on by default)
colour not the default colouring customer class for the map colour scale
sort not the default residential:desc sortKey:sortDir
utility a table row is expanded utility code; expands the row and opens its region (lowest precedence, after provider and region)

Two controls share the same URL: the sticky-nav Copy link button (#nav-share) and Copy link to this comparison in the comparison dialog. Both call syncUrl() first, then the Clipboard API with a hidden-textarea fallback, and confirm with a toast.

3.3 Filtering, sorting and comparison#

  • Filters are intersected: provider lens, NDA switch, region, type, grid and free text (utility name/code, region names, island, type, grid, data status). The table summary reports Showing N of 141 utilities · K with a published <month> residential rate; #clear-filters and the empty state's #empty-clear reset everything, including the provider lens.
  • Sorting compares the selected column, sorts null (NDA/missing) values last regardless of direction, breaks ties by name, and mirrors state into aria-sort on the column header plus an arrow glyph.
  • Comparison: adding a fourth provider silently drops the oldest and toasts about it; the tray appears when at least one is selected; the dialog opens only with two or more. It is a native <dialog> with showModal(), returns focus to the opener, plots the full residential history plus a latest-rate matrix, and links each row to its DOE source row and its static-API utility file. On mobile the wide matrix is replaced by stacked .compare-cards (CSS at max-width:700px).
  • The API explorer is not a live call either: it prints the __API_TABS__ payloads that were inlined at build time, with a link to the complete JSON file.

3.4 Accessibility behaviours that are part of the interaction model#

The map uses a roving-tabindex pattern — one focused region at a time, arrow keys move focus to the nearest region in that direction, Enter/Space selects, Escape clears — and a visible "skip the map" link jumps to the table. Custom dropdowns behave as ARIA listboxes (aria-expanded, aria-controls, aria-activedescendant, role option/listbox, Home/End/arrow/Enter/Escape/Tab support, type-to-filter). The NDA control is a role="switch" with aria-checked. Live regions (#aside, #table-summary, #compare-tray, #toast) announce changes. Motion respects prefers-reduced-motion; the whole page is designed to stay usable at 390 px.

4. Docs-site frontend#

4.1 Registry and generated shell#

tools/build-docs.py is the front end of the documentation site. The page list is explicit: the GROUP_DEFS list defines sidebar groups (label + blurb) and KNOWN_DOCS lists each page (id, source path, group, label, summary); additional research/*.md files are auto-discovered into the research group, with submission material explicitly excluded (SUBMISSION_RESEARCH). Output is one <id>.html per document plus index.html, shared assets/ and a machine-readable docs-manifest.json (page count, groups, sources, search-index stats).

Every page is rendered by page_html() with the same shell:

  • skip link, masthead (product/docs links, dataset version) and sticky subnav containing the mobile #docs-menu-btn drawer toggle and the #docs-search-open full-text trigger (Ctrl/Cmd+K, /);
  • a three-column docs-shell grid: sidebar #docs-sidebar (filter #doc-search / #doc-search-clear / #doc-search-hint, the #doc-nav group list, dataset footer), main#main, and the per-page TOC (aside.docs-toc / .toc-nav, generated from the h2/h3 headings);
  • breadcrumbs, page meta (source path, lines, size, words), Download raw, prev/next pager, footer, search dialog, and assets/docs.js with defer.

Markdown is rendered with markdown-it (CommonMark + tables), then transformed by transform_body() and heading_anchors(): fenced code gets a .code-block header and [data-copy] button, tables are wrapped in .table-scroll, blockquotes become callouts, headings get stable github_slug anchors. Links are rewritten by resolve_link(): registered documents become their .html page, the product page becomes ../map-table-prototype.html, repo files become ../../<path> raw-file links, and directories resolve to their registered README page. An unresolved internal link is appended to UNRESOLVED and fails the build (main() exits 1) — link only to files that exist.

4.2 Search with no server#

There is no search endpoint. build_search_index() walks the collected pages in registry order and emits a deterministic object with page labels, groups and one entry per h2/h3 section, each with the fragment id, heading and a capped snippet; plain-text documents get a single overview entry. The serialized index is substituted into docs_js() for the __DOCS_SEARCH_INDEX__ placeholder, i.e. it lives inside draft/docs/assets/docs.js.

javascript
{ "version": 1, "pages": [
  { "h": "frontend.html", "d": "Frontend architecture", "g": "Architecture",
    "s": [["", "Overview", "…snippet…"], ["section-slug", "Section label", "…snippet…"]] }
] }

The overlay (#docs-search-dialog, #docs-search-input, #docs-search-results, #docs-search-status) ranks title/label hits above heading hits above body hits, caps results per page, highlights matched terms, supports arrow keys/Enter/Escape and restores focus on close. The sidebar also has its own local filter over #doc-nav. Because the index is inlined, search works from file:// with zero network requests — asserted by the docs QA suite.

4.3 Navigation and mobile behaviour#

assets/docs.js also implements the mobile sidebar drawer (body.sidebar-open, #sidebar-backdrop, aria-expanded on #docs-menu-btn, Escape closes and returns focus), the code-copy buttons ([data-copy]), back-to-top, and TOC scrollspy via IntersectionObserver. assets/docs.css uses the shared BetterGov tokens and collapses the shell at 1200px (TOC hidden), 900px (single column, fixed off-canvas sidebar) and 560px (compact chrome), with print and reduced-motion rules. QA runs at 1280×900 and 390×844.

5. Review-pack frontend and the separation contract#

5.1 Two spaces, one generator#

tools/build-preview.py assembles a local review pack from the tracked artefacts. Its defining rule is that each page belongs to exactly one of two spaces, and the chrome says which:

Space Pages Chrome
B — fellowship submission (review material) pack home / (submission & review hub), /proposal.html, /answers.html, /research-pitch-deck-notes.html (challenge brief) submission context bar "Fellowship submission · review material"; nav/footer group submission and platform links separately
A — data platform (standalone product) /prototype.html, /api.html, /data-model.html, /readme.html, /research-*.html, /docs/ neutral context bar "Review copy · Open Energy Data Layer data platform" with a plain back-link; no submission links or copy

How the generator produces that split:

  • page(title, body, context="platform"|"submission", active) renders the shell from NAV_PLATFORM or NAV_SUBMISSION and the matching context bar, masthead and footer. A page's space is an explicit argument in main(), not a runtime toggle.
  • build_prototype() copies draft/map-table-prototype.html and rewrites repository-relative links to the pack's files/ tree. It adds no review chrome: /prototype.html is the production page and nothing else — byte-identical apart from those link rewrites.
  • copy_docs() copies draft/docs/, rewrites ../map-table-prototype.html to the pack copy and ../../<repo file> links to ../files/<repo file>, then injects the neutral review bar into each page and appends its CSS.
  • build_api() renders the OpenAPI contract as a standalone reference page; copy_files() builds files/ (data, contracts, docs sources, tools and tests) plus the package zip; write_assets() writes the pack CSS and copies fonts/logo/favicon.

The pack is served over Tailscale from a static file server (https://devvm1.tailf19a1a.ts.net/, direct port 8099). It is gitignored and local: rebuild it after the page and docs, never commit it, and never treat it as a deployment of the data platform itself.

5.2 The separation invariant#

WARNING

Warning: the data platform must contain no fellowship-submission material. Submission sources live only in plan/fellowship-proposal.md, plan/application-answers.md and research/pitch-deck-notes.md, and render only on the review pack's submission pages. This is a hard invariant, not a style preference.

Enforcement is layered, and a UI change must keep all of it green:

  • Product page — tests/qa.mjs and tools/validate.py assert no submission strip, no fellowship link or marker, no fellowship/submission copy in visible text, and no fellowship.bettergov.ph URL in the page source.
  • Docs site — tools/build-docs.py excludes the submission research document from auto-discovery; tests/qa-docs.mjs has a [separation] group asserting no submission documents in docs-manifest.json or on disk, no fellowship links or copy in the shell (masthead/subnav/sidebar/footer), and no links to submission documents from any page; tools/validate.py repeats the manifest/absence checks.
  • Review pack — the two contexts are separate code paths, and the pack's own README records grep-based self-checks (fellowship count must be 0 in prototype.html, review bars present on platform pages, submission bar on the hub).

If you add a page, a nav link or a footer column, decide its space explicitly. Never link a submission page from the data platform (page, docs, README, research, API) and never add submission names, deadlines or proposal language to the platform chrome.

6. UI invariants and pinned QA contracts#

6.1 Non-negotiable invariants#

  1. No external runtime requests. All fonts, marks, icons, geometry and data are inlined; the product page declares a default-src 'none' CSP; the docs site links only same-origin assets. The only outbound traffic is a user click on a citation anchor (target="_blank" rel="noopener"). Both QA suites assert zero external/third-party requests.
  2. Deterministic, byte-identical builds. No wall-clock times, randomness, set iteration or environment-dependent text in generated output. CI fails on any diff under draft/api/ or draft/docs/; validate.py --check-page proves the page rebuilds identically. The ingest timestamp comes from the snapshot, not the build run.
  3. Never hand-edit generated artefacts. draft/map-table-prototype.html, draft/docs/**, draft/api/v1/**, draft/assets/{geo,coverage-geo}.json, data/seed/** (except the data dictionary and illustrative plants.csv) and preview/** are outputs. Change the builder and rebuild.
  4. Accessibility is part of the contract, not a nice-to-have. One h1 per page, landmarks (header, nav, main, footer), a skip link to #main, labelled controls, visible focus, full keyboard operation (roving-tabindex map, ARIA listboxes/comboboxes, switch, native dialog focus return), live regions for async changes, and no horizontal overflow at desktop or 390 px.
  5. Provenance stays visible. NDA/invalid states render as badges, never as numbers; every plotted rate has a month and a source row or API file behind it; coverage claims carry their source label (law / OSM / DOE fallback).
  6. Separation is absolute. See §5.2.

7.2 Rebuild order and QA commands#

Consumers read earlier builders' output, so order matters wherever a surface is downstream. The full chain, from the repository root:

bash
python3 tools/build-geo.py              # optional: regenerate geometry from the pinned release
python3 tools/build-service-areas.py    # optional: service-area dataset
python3 tools/ingest-doe-rates.py       # data pipeline → data/raw, data/seed, page payload
python3 tools/build-api.py              # static JSON API → draft/api/v1
python3 tools/build-docs.py             # docs site → draft/docs
python3 tools/build-map-page.py         # product page → draft/map-table-prototype.html
python3 tools/build-preview.py          # local review pack → preview/ (gitignored)
python3 tools/validate.py               # static contracts; add --check-page after page changes
node tests/qa.mjs                       # product page: desktop 1440×900 + mobile 390×844
node tests/qa-docs.mjs                  # docs site over local HTTP: 1280×900 + 390×844

For a docs-only change the short loop is python3 tools/build-docs.py → node tests/qa-docs.mjs → python3 tools/validate.py. For a page change, also run python3 tools/validate.py --check-page to prove the committed page matches a fresh build. CI runs the same checks (.github/workflows/ci.yml): static validation, deterministic page rebuild, deterministic API/docs rebuild (git-diff), then both browser suites.

7.3 Common pitfalls#

  1. Hand-editing generated output. Edits to draft/docs/**, draft/map-table-prototype.html, draft/api/v1/** or preview/** are overwritten on the next build; CI diffs draft/docs/ and draft/api/ and fails. Always edit the builder/source.
  2. Adding an external asset or runtime fetch. A CDN stylesheet, web font, analytics tag or a fetch/XHR request breaks the self-containment invariant and both QA suites. Inline it through the builder instead (fonts and icons already have helpers).
  3. Breaking determinism. Wall-clock text (datetime.now() without a snapshot value), randomness, unsorted set/dict iteration or environment-dependent strings make the rebuild check fail. Prefer explicit sorted iteration and snapshot-derived timestamps.
  4. Renaming or removing a pinned id/selector. The QA suites and validate.py reference ids directly; a rename that is not mirrored in the tests (and in this page) is a failing build. Update builder + validator + QA + docs together.
  5. Hard-coding counts that drift. 141/18/1,648/108 and the validation-check counts appear in prose and assertions; derive them from the payload where possible and update all consumers when the data changes.
  6. Linking to files that are not published. build-docs.py fails on an unresolved internal link, and the review pack only copies known files into files/ — a new root-level file linked from a docs page must also be added to copy_files() in tools/build-preview.py or the preview link check will 404.
  7. Adding submission material to the platform. A fellowship link, deadline or proposal sentence in the page, docs, README or research breaks the separation invariant (§5.2) and fails both QA suites and the validator.
  8. Skipping the mobile check. 390 px is a tested viewport: the sticky nav becomes a menu, the table pins its first column, the comparison matrix becomes cards, and the docs sidebar becomes a drawer. Verify no horizontal overflow after interaction, not just on load.
  9. Printing the giant generated files. draft/map-table-prototype.html is ~1 MB with inlined data, fonts and geometry; never cat it or paste large ranges. Inspect it with grep -n, sed -n 'A,Bp' or a targeted read on the builder source instead.

7.4 Adding a docs page#

The docs site has no auto-discovery for top-level markdown (only research/*.md). To publish a new page: add the markdown source under draft/, add a KNOWN_DOCS dict to tools/build-docs.py (unique id → <id>.html, source path, group, label, summary), and, for a new navigation group, add a GROUP_DEFS entry (id, label, blurb) in the position you want it to appear. Rebuild draft/docs/; the manifest page count, sidebar, search index and prev/next pager all update automatically. Then run node tests/qa-docs.mjs and python3 tools/validate.py. This page is registered under a separate architecture group alongside the component map.

8. Reading order for a new contributor or agent#

  1. README.md — what the product is, the dataset at a glance, repository layout.
  2. CONTRIBUTING.md — setup, build commands, and the data/page/API rules (the page rules are the frontend contract in prose).
  3. tests/README.md — what validation and browser QA prove, and what CI enforces.
  4. AGENTS.md (repository root) — component map, task routing, cross-cutting invariants and the finish checklist.
  5. draft/component-map.md — the human component/contract map (renders at /docs/component-map.html), plus the per-area agent maps tools/AGENTS.md, data/AGENTS.md, draft/AGENTS.md and tests/AGENTS.md.
  6. This page — the frontend-specific map: surfaces, injection, runtime state, docs/review-pack frontends and the UI rules.
  7. The builder source: read the tools/build-map-page.py docstring, then the shell functions and module markers in §2; for the docs site read tools/build-docs.py (page_html, docs_js, build_search_index); for the pack read the tools/build-preview.py module docstring, which states the two-space split.
  8. draft/data-model.md, draft/api-docs.md and draft/openapi.yaml — the data/API contracts a UI change must keep honest. The pipeline counterpart to this page is draft/backend.md.

The fastest safe workflow for any UI task: identify the surface and builder in §1, find the owning function/module in §2–§5, make the change in the builder only, rebuild in the order of §7.2, then run the pinned QA suites and the deterministic rebuild check before reporting back.
