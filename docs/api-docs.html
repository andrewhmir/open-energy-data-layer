API · documentation

Open Energy Data Layer — Philippine Electricity Rates Data API

draft/api-docs.md · 673 lines · 37 KB · 4,801 words

Download raw All docs

A small, public, read-only JSON API over the DOE Electricity Rates & Power Market Monitor workbook: monthly average electricity rates for residential, commercial, industrial and blended generation-charge customers across 141 distribution utilities and electric cooperatives in 18 PSA PSGC regions, 107 monthly columns from 2018-01 to 2026-11 (latest published month 2026-10). Built from the same snapshot as this page by tools/build-api.py.

The API is a set of plain JSON files, not a running service: every endpoint below is one file under api/v1/, served read-only with no authentication. The contract is openapi.yaml (OpenAPI 3.1); the machine-readable catalog is api/v1/index.json.

Overview#
API version 1.0 (contract version, stable across dataset snapshots)
Dataset version 2026-11-10 (retrieval date; changes with every new snapshot)
Latest published month 2026-10 (the source's 2026-11 column is not yet published)
Coverage 141 utilities/electric cooperatives · 18 PSGC regions · 4 customer classes · 107 months
Service-area coverage 141 utilities — 141 with LGU-level rows, 0 with barangay-only rows, none needing the region fallback
Endpoints 19 static GET routes: 17 rate/quality/source + 2 provider service-area
Rate unit PHP per kWh — the published monthly average, exact to the source's two decimals
Upstream source Department of Energy (DOE), Electricity Rates & Power Market Monitor
Source retrieved 2026-11-10T17:00:34+08:00 (CSV export of the public Google Sheet)
Licence Not stated by publisher — see Sources & attribution
Auth None. Public read; fair-use conditions apply.
Format Static JSON files with a {meta, data, next_cursor} envelope

What it is: a provenance-first view of the DOE workbook with stable utility codes, PSGC geography, explicit source states and checksums behind every value — plus a sourced provider service-area (coverage) layer for the page's provider filter, with per-row provenance, its own source registry and its own licences. Coverage is derived data, not a DOE rate publication.

What it is not: an official DOE product; a live feed; a query API (there are no query parameters); a bill-component breakdown (generation, transmission, system loss, distribution, subsidies, FIT-All and taxes are not in the source); and it contains no imputed, interpolated or modelled values.

Base URL & access#

The API is not hosted as a service yet. The canonical origin is set at deployment; in this repository the files are served at api/v1/ (relative to this draft/ directory), which the page links to directly. No domain is invented here. The OpenAPI server URL is the relative api/v1 (no leading slash), so it resolves against wherever the spec or page is served, not the host root.

All requests are GET (or HEAD) on static files:

  • No authentication, no API key, no request body.
  • CORS: when served by the deployment host, responses should carry Access-Control-Allow-Origin: *, following the BetterGov Budget API convention.
  • Caching: responses should carry Cache-Control: public, max-age=300, s-maxage=3600. Every file is immutable within a dataset_version, so aggressive client-side caching is safe.
  • Fair use: identify heavy automated use with a descriptive User-Agent.
  • Errors: a path that is not a served file returns the host's normal 404. This snapshot has no JSON error envelope; the machine-readable error format (bad_request, not_found, method_not_allowed, …) is reserved for a future dynamic deployment.
bash
# Relative to this draft/ directory; prepend the deployment origin when hosted.
curl -s api/v1/meta.json | jq '.data.coverage'
curl -s api/v1/rates/latest/residential.json | jq '.data.stats'
curl -s api/v1/utilities/MERALCO.json | jq '.data.series.residential.counts'
curl -s api/v1/regions/1300000000.json | jq '.data.region'
curl -s api/v1/changes/latest.json | jq '.data.movements[0]'
curl -s api/v1/sources/SRC-DOE-RATES.json | jq '.data.tabs'
curl -s api/v1/service-areas.json | jq '.data.coverage'
curl -s api/v1/service-areas/MERALCO.json | jq '.data.rows[:2]'

Units. Every rate is in PHP per kWh (currency: "PHP", unit: "PHP per kWh" in every meta). No rescaling, no rounding beyond the source's own two decimals. Amounts are averages as published; they are not bills and not estimates.

Identifiers. utility_code is this dataset's stable slug (e.g. MERALCO, ABRECO) — not an official DOE/ERC/NEA identifier. region_psgc is the 10-digit PSA PSGC region code (e.g. 1300000000 for NCR). Months are YYYY-MM. Coverage rows join the same geography through region_psgc / province_psgc / adm3_psgc / adm4_psgc (canonical 10-digit PSGC); the API publishes coverage areas as codes, not as polygons.

Explicit source states. Every utility/class/month cell has exactly one state:

State Meaning
published The source workbook has a numeric rate; it is published here as-is.
nda "No Data Available", as published by the source. Never zero, never estimated.
missing The month column exists but the cell is blank / not yet published (all of 2026-11).
invalid The cell failed extraction validation; no value is published for it (1 cell in 2026-10).

null never means zero. An aggregate is only computed over published values.

Conventions#

Envelope#

Every data file returns the same envelope:

json
{
  "meta": {
    "api_version": "1.0",
    "dataset": "doe-electricity-rates",
    "dataset_version": "2026-11-10",
    "latest_month": "2026-10",
    "generated_at": "2026-11-10T17:00:34+08:00",
    "currency": "PHP",
    "unit": "PHP per kWh",
    "source": {
      "id": "SRC-DOE-RATES",
      "publisher": "Department of Energy (DOE)",
      "title": "Electricity Rates & Power Market Monitor",
      "canonical_url": "https://doe.gov.ph/data-and-prices/electricity",
      "retrieved_at": "2026-11-10T17:00:34+08:00",
      "extraction_method": "csv_export"
    },
    "attribution": "Source: Department of Energy (DOE) — Electricity Rates & Power Market Monitor, retrieved 2026-11-10T17:00:34+08:00. …",
    "licence": { "name": "Not stated by publisher", "note": "…", "url": null },
    "service_area": {
      "detail_counts": { "total": 141, "lgu": 141, "barangay": 0, "region": 0 },
      "sources": [{ "source_id": "SRC-RA-12146", "licence": { "name": "Public document (Philippine law)", "url": null } }, "…"],
      "note": "Service-area coverage is derived data, not a DOE rate publication; see /v1/service-areas.json."
    },
    "disclaimers": [{ "id": "disclaimer-unofficial", "title": "Unofficial compilation.", "text": "…", "url": "#disclaimers" }],
    "count": 141
  },
  "data": { "…": "endpoint-specific payload" },
  "next_cursor": null
}
  • meta.count is the number of primary records in data (rows for a list, months for the month series, 1 for a single record).
  • next_cursor is always null in this static snapshot: there is no pagination and no query layer. The field is reserved so a future dynamic deployment can paginate without breaking clients.
  • meta.service_area states the coverage context: how many utilities are covered at LGU, barangay or region level, and which sources (with their licences) back the layer. Coverage is derived data, not a DOE rate publication — see disclaimer-coverage.
  • api/v1/index.json (the catalog) and api/v1/openapi.json (the contract) are documents, not envelope responses.

Errors#

Static files do not emit JSON errors; unknown paths are the host's 404. A future dynamic deployment can adopt the BetterGov Budget API error shape — { "error": "not_found", "message": "…" } with slugs bad_request, bad_cursor, not_found, method_not_allowed, not_loaded, query_failed — without changing any success payload.

Versioning#

api_version (1.0) is the JSON contract version. dataset_version (2026-11-10) is the retrieval date; a new snapshot gets a new dataset_version and the old files are never silently rewritten. The changelog is x-changelog in openapi.yaml (contract 1.0.0 / dataset 2026-11-10; the v1.1 service-area coverage layer is an additive change — 19 routes now, but the envelope and every rate endpoint are unchanged).

Endpoint reference#

All paths are GET-only static files and every served path ends in .json; prepend the deployment origin or, in this repository, read them relative to draft/. Nineteen routes: 17 discovery, rate, quality, utility, region, change and source routes, plus 2 provider service-area routes. Four routes are per-entity file families — the catalog (api/v1/index.json) names a concrete example file for each (/v1/utilities/MERALCO.json, /v1/service-areas/MERALCO.json, /v1/regions/1300000000.json, /v1/sources/SRC-DOE-RATES.json); substitute the entity code to read any member, e.g. api/v1/service-areas/<CODE>.json (141 files).

Service areas & provider coverage#

The DOE workbook assigns each utility exactly one region. That is enough to filter by region, but it is not the utility's service area: an electric cooperative usually covers a handful of municipalities, and Meralco's franchise spans three regions. The coverage layer publishes a sourced, row-level service area so the provider filter can show what a utility actually covers and every coverage row can be traced to a source. It is derived data, not a DOE rate publication.

Object Where Shape
Coverage summary meta.service_area in every response; utilities.json rows {detail, source_ids, regions, lgu_count, province_count, barangay_count}
Full coverage utilities/<CODE>.json → service_area; service-areas/<CODE>.json → service_area summary + provinces[], lgus[], barangays[], barangay_provinces[], note
Coverage rows service-areas/<CODE>.json → rows[] (published from the seed CSV) utility_code, area_level, source_id, region_psgc/region_short/region_name, province_psgc/province_name, adm3_psgc/lgu_name, adm4_psgc/barangay_name, coverage_note
Source registry service-areas.json → sources[]; sources.json → coverage_sources[]; meta.json → service_area.sources[] {source_id, short_title, publisher, dataset_title, page_url, revision_id, retrieved_at, licence {name, url, note}, attribution, notes, used_for {rows, utilities, rows_by_area_level}}

area_level is one of:

  • lgu — one covered city/municipality (adm3_psgc, canonical 10-digit PSGC).
  • barangay — one covered barangay (adm4_psgc), used where the franchise grants barangays only.
  • region — a single fallback row that repeats the DOE workbook region when no LGU-level source is available. It means "not sourced at LGU level", never "one LGU".

Coverage at this snapshot: 141 of 141 utilities have LGU-level coverage, 0 have barangay-only coverage and 0 publish only the region-level fallback (1,648 LGU rows, 17 barangay rows, 0 fallback rows, 1,602 distinct LGUs, 10 multi-region utilities). Caveats — read before using coverage as a filter#

  • Multi-region coverage. 10 utilities have published coverage in more than one region: MERALCO (the franchise-law case — RA 12146 Section 1 enumerates its LGUs in NCR, Region III and Region IV-A plus 17 Pampanga barangays, while the DOE workbook lists MERALCO under NCR only) and 9 other cross-region / PSGC-reassignment franchises whose published LGU areas span regional boundaries. coverage.regions lists every PSGC region the rows touch; a filter built from the DOE single-region field alone understates their footprint.
  • PSGC reassignment is not an error. Three utilities — PROSIELCO, SIASELCO and SULECO — publish coverage in a different region than their DOE workbook row because PSGC 3Q 2026 reassigned Sulu to Region IX and Siquijor to NIR; their coverage.note documents this. Use the published coverage for the provider filter and keep the DOE row as the rate-aggregation region.
  • Partial province coverage. coverage_note is the source's own qualification. For example, RA 12146 covers 20 of Cavite's 23 LGUs (it omits Amadeo, General Emilio Aguinaldo and Gen. Mariano Alvarez relative to the prior franchise; the reason is not stated in the law), and only parts of Batangas, Laguna and Quezon. Do not round partial provinces up to full coverage.
  • Barangay-level coverage. Pampanga has no whole-LGU coverage in the MERALCO franchise — only 17 barangays in Apalit, San Simon and Candaba. area_level: barangay rows count barangays, not LGUs; never render the touched LGUs as fully covered.
  • Region fallback. A utility whose coverage.detail is region has one fallback row repeating its DOE region. That is an explicit "not sourced at LGU level", not a claim that it serves the whole region or a single LGU.
  • Franchise ≠ billing territory. Coverage encodes the legislative franchise / published operator area; it is not verified household-level service territory. Distribution service can differ (unenergized areas, ERC-approved arrangements, contested areas). Use it as a coverage and filter layer, not as proof of who bills an address.
  • Codes, not polygons. Coverage rows join the map geometry through canonical 10-digit adm3_psgc / adm4_psgc; the API does not publish polygons. NCR has no province layer, so provinces[] for Meralco lists the map package's NCR districts under the same "Metro Manila" name; use lgus[] / adm3_psgc for LGU-level joins.
  • Validation. Seven coverage checks are recorded at ingest (coverage_checks in api/v1/validation.json, summarised in api/v1/health.json); the API build additionally re-verifies that every utility's coverage block matches its published rows and that both seed files match their pinned rows/bytes/SHA-256.

Disclaimers#

Every response carries these five disclaimers in meta.disclaimers (id / title / text); keep them with any figure you republish.

  1. disclaimer-unofficial — Unofficial compilation. This is an independent compilation of a public DOE workbook, not an official DOE publication. Verify every figure against the source before citing or acting on it.
  2. disclaimer-licence — Upstream reuse terms unconfirmed. The DOE workbook publishes no explicit reuse licence; terms are to be confirmed with DOE. No licence is asserted over the upstream data by this API.
  3. disclaimer-nda — NDA, missing and invalid are preserved, never imputed. NDA is the source's "No Data Available"; missing is a month not yet published; invalid is a cell that failed validation. null never means zero and is never an estimate.
  4. disclaimer-rates — Rates are monthly averages as published. Actual bills vary by consumption, charges, subsidies and timing. Figures are informational only and not financial advice.
  5. disclaimer-coverage — Coverage is derived data, not a DOE rate publication. Service-area coverage is derived from franchise law (RA 12146 for MERALCO), the DOE workbook region column as a fallback, and, where present, the OpenStreetMap Wiki operator table (CC BY-SA 2.0) and the Wikipedia distribution-utility list (CC BY-SA 4.0). A franchise area is not verified household-level billing territory; region-level rows are a fallback, not LGU-level confirmation. Keep each source's attribution and licence.
