Component map & agent guide

draft/component-map.md · 134 lines · 11 KB · 1,286 words

Download raw All docs

This repository is a deterministic static-build pipeline: raw DOE workbook snapshots become validated seed data, which becomes a single-file product page, a read-only static JSON API, a generated docs site and a local review pack. Nothing is served by an application server — every artefact is a file produced by a Python builder.

Use this page to find where to edit and what to run. It is the human version of the repository's AGENTS.md maps; the same content drives coding agents. The rendered copy lives at /docs/component-map.html; the markdown source is draft/component-map.md, registered in the docs builder's KNOWN_DOCS registry (tools/build-docs.py) so it renders with the rest of the docs site.

NOTE

Note. Every command below is meant to be run from the repository root. Build outputs under data/seed/, draft/, preview/ and /tmp/qa-* are generated — edit the source, never the artefact.

Cross-cutting invariants#

  1. Deterministic, byte-identical builds. No wall clock, randomness or unordered iteration in output; CI diffs draft/api and draft/docs, and validate.py --check-page rebuilds the page twice and compares it to the committed file.
  2. Generated files are read-only. data/raw/** is immutable publisher bytes; data/seed/**, draft/map-table-prototype.html, draft/api/v1/**, draft/docs/** and draft/assets/{geo,coverage-geo}.json are generated. Fix the generator and rebuild.
  3. Self-contained output. The page and docs inline fonts, brand, geometry and data; no CDN, web font, analytics or fetch/XHR. Outbound traffic exists only when a reader clicks a citation link; QA asserts zero external/third-party requests.
  4. Provenance, no imputation. published / nda / missing / invalid are preserved as distinct states; aggregates use published values only and carry the reporting count; every value has a source row and a SHA-256 over the raw bytes.
  5. Hard separation: data platform ≠ fellowship submission. The data platform documented here contains no submission material; submission sources (plan/fellowship-proposal.md, plan/application-answers.md, research/pitch-deck-notes.md) render only on the review pack's submission pages. Both QA suites and validate.py enforce the separation.
  6. Accessibility and pinned contracts. Desktop and mobile, semantic landmarks/labels, visible focus, full keyboard operation; pinned ids, roles and counts are contracts shared by builder, validator, QA and docs.
